后续修正：两栏手动缩放已拆分为独立操作，滚动同步只同步阅读位置。下文的“按同一倍数同步缩放”为本轮历史行为，当前行为见 [INDEPENDENT_COLUMN_ZOOM.md](INDEPENDENT_COLUMN_ZOOM.md)。

## 原因与改动

前一轮保存手动倍率的规则会让扩宽后的 PDF 继续保持很小的尺寸。横向恢复把滚动原点限制为非负值，小页面居中所需的负偏移因此丢失，出现页面贴左。PDFKit 的自动缩放还包含整页适配逻辑，无法单独表达按栏宽缩放。固定 200 pt 的最小栏宽会改变侧栏打开后的分栏比例。

- 新增 `PDFViewportLayout`，统一计算适配倍率和页面中心。按文档最宽页面、旋转方向和显示裁切框测量，左右各留最多 8 pt；页面宽度缓存随文档或显示框变化失效。
- PDFKit 使用显式倍率，应用自己持有适配模式。`PDFColumnReadingState.autoScales` 保留旧 JSON 字段名，语义为应用控制的按宽度适配。
- 视口协调器发现栏宽变化、首次打开或隐藏栏重新显示时切回适配；分隔线跟踪期间立即恢复缩放与阅读锚点，松开后完成同一事务。
- 水平位置由页面几何中心计算，允许负滚动原点。点击、滚动通知和布局恢复共用同一居中入口，双栏同步只改变纵向阅读位置。旧横向滚动比例字段保留解码兼容。
- 分栏允许 5%–95% 的比例；右侧栏改变外层画布宽度，内部分栏按原比例缩放。
- 手动缩放仍可使用；同步开启时，两栏分别以自己的适配倍率乘同一倍数，保持各自居中。后续宽度变化恢复适配。重开阅读器恢复文档和纵向阅读位置，同时按当前窗口适配。

前一轮的独立阅读锚点、页首/页尾边界处理、延迟事件隔离和文档对校准继续保留。
