### B01：缩放倍率重复应用

位置：`Sources/ReaderTabViewController.swift:4446`、`:3260`、`:4518`。

`zoomColumn` 先改变当前 PDF 的倍率，`PDFViewScaleChanged` 通知立即把这个倍率复制到另一栏。随后 `zoomColumn` 又对另一栏乘一次倍率，通知再把结果复制回来。因此一次 `×1.15` 最终成为 `×1.15²`。全局缩放循环逐栏修改，同样经过这条路径；缩小也存在相同重复逻辑。

较短复现：开启同步，将两栏设为 100%，点击任意一栏的放大按钮，或使用菜单放大。两栏变为 132.25%。

修复方向：让一次用户操作只产生一次倍率计算，并统一由一个同步入口分发；程序性更新需要抑制通知回灌。

### B02：隐藏栏参与同步，单栏切换跳页

位置：`Sources/ReaderTabViewController.swift:60`、`:3235`、`:3247`、`:4300`。

单栏布局把隐藏栏宽度设为 0。PDFKit 随之重算自适应比例，本机实测隐藏栏降至 `0.1`，其视口在文档坐标中一次覆盖数页。`clipViewBoundsChanged` 把这类尺寸变化当作滚动，且 `syncScroll` 未检查当前是否双栏、来源栏是否可见、布局是否正在改变。隐藏栏于是能够反向推动可见栏。

最短复现只需要：默认同步双栏 → 滚到文档中段 → 切“仅原文”。实测可见原文从 4.40 变成 8.05，无需先互换、拖动或连续缩放。切“仅译文”也复现大幅位移。

修复方向：在布局变更期间冻结同步，记录可见栏锚点，等待 PDFKit 完成尺寸计算后恢复；同步事件只接受可见且已完成布局的栏。

### B03：模式切换丢弃手动缩放

位置：`Sources/ReaderTabViewController.swift:4299`。

`applyDisplayMode` 每次都将可见 PDF 的 `autoScales` 设为 `true`，双栏时两边都设置。用户选择的手动缩放模式及倍率没有保存，也没有区分首次布局与模式切换。

复现：关闭同步 → 双栏手动缩放 → 切单栏 → 再放大 → 回双栏。探针记录原文由手动 160% 进入自适应约 119.44%。

修复方向：按栏保存缩放模式和用户倍率，单独处理首次自适应布局；模式切换采用明确的倍率/可见内容恢复策略。

### B04：侧栏开关重置缩放

位置：`Sources/ReaderTabViewController.swift:4562`。

右侧栏开合后投递的主队列任务，无条件将左右 PDF 的 `autoScales` 都设为 `true`。该逻辑在关闭同步时也执行，同时涉及隐藏栏。

复现：独立模式，两栏分别手动设为 160%、130% → 开关右侧栏 → 等待一轮布局。倍率重新由列宽决定，手动模式丢失。

修复方向：侧栏仅改变可用画布大小；对自适应栏重新计算，对手动缩放栏保留状态，并恢复阅读锚点。

### B05：独立模式隐藏栏恢复后位置错误

位置：`Sources/ReaderTabViewController.swift:4299`、`:4307`。

复现：关闭同步 → 原文位置 5.40、译文位置 7.40 → 仅原文 → 放大 → 双栏。原文最终位置接近原值，译文变成约 3.57。

此路径关闭了同步，独立展示了恢复隐藏 PDF 的问题。控制器在修改可见性、零宽布局、设置自适应和重新布局之间没有保存、恢复两栏各自位置。

修复方向：每栏保存文档身份和逻辑阅读锚点，在该栏恢复有效尺寸并完成 PDFKit 布局后恢复。

### B06：隐藏栏覆盖阅读进度

位置：`Sources/ReaderTabViewController.swift:3274`、`:3334`。

`scheduleReadingPositionSave` 只检查整个阅读器根视图是否隐藏，没有检查 `column.isHidden`。隐藏栏的尺寸或页码通知同样可以更新 `lastReadingColumn` 和论文唯一的 `readingPosition`。

复现：开启同步 → 双栏 → 仅译文 → 等待布局。探针读到保存侧别为 `original`。重新打开时会据此选择错误的恢复栏。

修复方向：保存入口仅接受用户正在阅读的可见栏；程序性布局、恢复与同步过程中的通知应隔离。

### B07：临时尺寸约束写回用户分栏比例

位置：`Sources/ReaderTabViewController.swift:46`、`:4250`、`:4952`。

`setPosition` 将受最小宽度限制的实际比例经 `onSplitRatioChanged` 写回 `columnSplitRatio`。`splitViewDidResizeSubviews` 也从实际宽度覆盖该变量。窗口缩小或侧栏占用空间时产生的临时钳制，因而成为新的用户偏好，宽度恢复后不再使用原比例。

复现：大窗口拖成 80:20 → 开侧栏 → 请求缩小窗口 → 关侧栏 → 放大。实测最终约 76.77:23.23。

修复方向：分别记录用户期望比例和受当前空间约束的显示比例，只有实际用户拖拽才修改期望比例。

### B08：拖动折叠侧栏与开关状态脱节

位置：`Sources/ReaderTabViewController.swift:4538`、`:4952`、`:4981`。

外层分隔允许右侧栏折叠，但拖拽折叠没有同步 `isDrawerOpen` 及按钮状态。按钮后续仅执行 `isDrawerOpen.toggle()`，所以第一次点击会把旧的 `true` 切为 `false`，侧栏继续隐藏。

复现使用了 AppKit 鼠标按下、拖动和松开事件：将侧栏拖宽 70pt 正常生效，再拖到右侧收起，点击按钮后 `drawer.isHidden` 仍为 `true`。

修复方向：折叠状态变化时更新控制器状态和按钮，或以当前实际展开状态作为动作依据。

### B09：互换后的栏位控制对象错误

位置：`Sources/ReaderTabViewController.swift:4318`、`:4387`、`:4417`。

互换动作只改变 `splitView` 子视图顺序。“左栏”的页码、跳页和缩放仍引用 `leftCol`，“右栏”仍引用 `rightCol`，标签和提示也没有按视觉位置重映射。

较短复现：关闭同步 → 左右互换 → 点击“左栏下一页”。视觉左侧译文保持原页，视觉右侧原文移动。

修复方向：建立视觉左/右栏的统一解析入口，并让页码显示、翻页、缩放和提示共用该映射。

### B10：窄窗口顶栏挤压

位置：`Sources/ReaderTabViewController.swift:611`、`:738`、`:867`。

固定 226pt 模式控件、固定搜索框和绝对居中的双栏工具组同时存在，并通过左右不重叠约束挤压内部控件。缺少适应窄宽度的布局策略和合理的交互控件最小宽度。

复现：缩至允许的较窄窗口 → 双栏 → 展开搜索。实测四个翻页按钮各 10pt 宽，图标和点击区域被压缩。该次记录窗口在约束作用下最小实际宽度为 1153pt，并未达到代码声明的 1020pt。

修复方向：增加紧凑布局或工具溢出入口；明确控件最小交互尺寸，并按实际可用空间布局。

## 已验证的边界及判定方式

- AppKit 的真实鼠标跟踪路径可将内分隔线拖动 100pt，侧栏分隔线拖动 70pt；测试覆盖了随后的缩放和单双栏切换。
- 12 次模式、侧栏和窗口尺寸交替，以及缺少译文、横向 PDF、交替旋转页面各 8 次组合操作和窗口最大化，均未复现可见 PDF 外层面板宽高归零或越出画布。
- 单独等待切换布局完成后，显示出来的 PDF 可以恢复正常的自适应倍率。因此，未把隐藏栏的瞬时 10% 倍率单独列为“可见 PDF 永久缩成 10%”；B02、B05、B06 依据实际发生的阅读位置变化和保存错误成立。
- 缩放会改变视口覆盖范围。返回测试确认视口起点在返回前后相同，因此单纯的视口中心变化未计为返回功能缺陷（A08-control）。
- 结果对应本机 PDFKit；未对其他 macOS 版本的渲染差异作出验证。

## 建议的处理顺序

1. 将模式切换、分隔线调整、窗口缩放和侧栏开合作为完整布局过程处理：记录锚点、冻结同步和进度保存、完成布局、恢复锚点。
2. 把可见性、视觉栏位、PDF 身份、缩放模式、阅读位置和用户期望分栏比例纳入明确状态；避免从布局中的临时尺寸反推用户偏好。
3. 合并缩放同步入口，处理侧栏拖拽折叠状态，补齐窄窗口工具栏布局。
4. 按报告中的探针逐项修复，并将适当的检查转成正常回归测试；随后处理搜索生命周期、目录来源及附加 PDF 恢复问题。
